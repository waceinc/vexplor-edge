# 원격 수집기(VEXPLOR Edge) 설치

*English: [install.md](install.md)* · 사용법: [사용법.md](사용법.md) · 규격: [계약.md](계약.md)

VEXPLOR Edge 는 공장 안 PC 한 대에서 동작하는 프로그램입니다. **서버에서 사람이 승인한 읽을 목록**에 있는 PLC · 제어기만
읽고, 서명한 묶음을 HTTPS 로 밖으로 보냅니다. 읽기만 하고, 포트를 열지 않으며, 원격 정지가 없습니다. 같은 프로그램이 규격 `vexplor.edge/1` 을
따르는 서버(VEXPLOR AAS Studio · VEXPLOR Logic Studio Cloud)에 모두 연결됩니다.

## 1. 어디에 두나 — 배치 두 가지

| | A. DMZ · 사무망 | B. 설비망 |
|---|---|---|
| PC 위치 | 사무망과 설비망 사이, 양쪽에 닿는 자리 | 설비망 안, 서버로 나가는 길이 있는 자리(흔히 프록시 경유) |
| 설비 쪽 방화벽 | PC → PLC 포트(OPC UA 4840, Modbus 502, MQTT 1883/8883, 1.2.0 부터 S7 102 · PLC 에 정한 MC 포트) | 새로 열 것 없음 |
| 바깥 쪽 방화벽 | PC → 서버 443(또는 프록시) | PC → 프록시(또는 서버 443) |
| PC 로 들어오는 연결 | **없음** | **없음** |

설비망에서 밖으로 나가는 길이 전혀 없으면 A, 설비망의 PC 한 대가 현장 프록시로 나갈 수 있으면 B 를 고릅니다. 두 경우 모두
안으로 들어오는 연결은 없습니다.

## 2. 연결하는 곳(전부)

| 목적지 | 이유 | 언제 |
|---|---|---|
| 설정의 서버 주소 443(또는 `proxy` 경유) | 읽을 목록 · 묶음 · 등록 | 늘 |
| 승인된 읽을 목록의 PLC 엔드포인트(OPC UA · Modbus TCP · MQTT, 1.2.0 부터 S7 · MC) | 값 읽기 | 승인 뒤 |
| `update.manifestUrl` | 새 판 알림, 하루 한 번 | 설정했을 때만 |

이 밖의 연결은 없습니다. 시험이 모든 연결 시도를 기록해 이를 확인합니다(STD-009 T9).

## 3. 설치 — 원클릭

지원: **Linux x64 · arm64**(systemd), 1.2.0 부터 **Windows x64**(Windows 서비스 — 아래 [Windows](#windows)). 공장 PC는 서버에 **https** 로 연결합니다(같은 PC 안 시험만 http 허용).

**서버 화면에서(VEXPLOR AAS Studio 2.7.0 이상)** — 「설정 → 원격 수집기」 → **「+ 수집기 연결」**. 서버 주소와 지금 읽을
목록을 확인하고 「연결 명령 만들기」를 누르면 한 줄이 나옵니다. 「이 목록을 바로 읽게 승인」을 켜 두면 승인도 함께 끝납니다.
꺼져 있으면 관리자가 같은 화면에서 「원격 수집 켜기」를 누릅니다.

**공장 PC에서** — 그 한 줄을 터미널에 붙여 넣습니다.

```bash
curl -fsSL https://github.com/waceinc/vexplor-edge/releases/latest/download/get.sh | sudo sh -s -- --server https://aas.example.com --code 7KQ4-M2XD-9PRT
```

`get.sh` 는 그 PC 의 CPU(x64 · arm64)에 맞는 꾸러미를 같은 릴리스에서 받아 `SHA256SUMS` 와 대조하고, 맞을 때만 안의
`install.sh` 를 실행합니다. 뒤에 붙인 선택은 설치기에 그대로 전달됩니다 — `--proxy http://proxy:3128` · `--ca-file corp-ca.pem` ·
`--credentials-file credentials.json`(4절) · `--name "1라인"`(기본은 PC 이름).

화면에 그 PC 이름과 **「받는 중」**이 뜨면 끝입니다. 미리 승인하지 않았으면 「연결된 수집기」에서 「목록 보고 승인」을 누릅니다 —
승인을 기다리는 동안 수집기가 10초마다 서버에 묻기 때문에, 승인하면 곧바로 읽기 시작합니다. 승인 전에는 아무것도 읽지 않습니다.

### 직접 설치(인터넷이 막힌 PC)

[Releases](https://github.com/waceinc/vexplor-edge/releases)에서 `vexplor-edge-<판>-linux-x64.tar.gz`(또는 `linux-arm64`)와
`SHA256SUMS` 를 다른 PC 에서 내려받아 옮긴 뒤:

```bash
sha256sum -c SHA256SUMS --ignore-missing
tar xzf vexplor-edge-<판>-linux-x64.tar.gz && cd vexplor-edge-<판>
sudo ./install.sh --server https://aas.example.com --code 7KQ4-M2XD-9PRT [--proxy http://proxy:3128] [--ca-file corp-ca.pem]
```

코드는 서버 화면 「연결 명령 만들기」가 보여 주는 명령의 `--code` 값입니다(24시간 · 한 번만 유효).

프로그램은 `/opt/vexplor-edge`, 설정은 `/etc/vexplor-edge/edge.json`, 키와 대기열은 `/var/lib/vexplor-edge`(서비스
계정만)에 둡니다. 서비스 `vexplor-edge` 는 권한을 줄인 상태로 동작합니다(새 권한 없음, 시스템 읽기 전용, 상태 폴더만 쓰기, 특수
권한 없음). 기록: `journalctl -u vexplor-edge`. 판 확인: `/opt/vexplor-edge/vexplor-edge --version`.

### Windows

1.2.0 부터입니다. Windows 10 또는 Server 2016 이상, x64, Windows PowerShell 5.1(Windows 에 들어 있음). 서버 화면에서 **Windows**
탭을 고르면 서버 주소와 코드를 채운 같은 명령이 나옵니다. 명령 프롬프트나 PowerShell 을 **「관리자 권한으로 실행」**으로 열고 붙여
넣습니다.

```bat
powershell -NoProfile -Command "[Net.ServicePointManager]::SecurityProtocol=[Net.ServicePointManager]::SecurityProtocol -bor 3072; & ([scriptblock]::Create((irm https://github.com/waceinc/vexplor-edge/releases/latest/download/get.ps1))) -Server https://aas.example.com -Code 7KQ4-M2XD-9PRT"
```

`get.ps1` 은 같은 릴리스에서 `vexplor-edge-<판>-win-x64.zip` 을 받아 `SHA256SUMS` 와 대조하고, 맞을 때만 안의 `install.ps1` 을
실행합니다. 코드 뒤에 붙인 선택은 설치기에 그대로 전달됩니다 — `-Proxy http://proxy:3128` · `-CaFile corp-ca.pem` ·
`-CredentialsFile credentials.json` · `-Name "1라인"`(기본은 PC 이름) · `-NoService`.

- **실행 정책**은 바꾸지 않습니다. 명령은 `get.ps1` 을 글로 받아 실행하고(실행 정책은 스크립트 파일에만 걸립니다), 그 안에서 띄우는
  설치기 프로세스 하나에만 그 파일 한정으로 `-ExecutionPolicy Bypass` 를 줍니다.
- **TLS 1.2** 를 그 창에서만 켭니다 — Windows 10 / Server 2016 의 Windows PowerShell 5.1 은 기본으로 TLS 1.0 만 쓰고 GitHub 은
  이를 받지 않습니다(명령의 `3072` 가 TLS 1.2 입니다).
- **프록시**: `-Proxy` 는 내려받기에 쓰이고 `edge.json` 에도 들어갑니다. 없으면 내려받기는 Windows 에 설정된 프록시(인터넷 옵션)를
  씁니다. 첫 내려받기(`irm …/get.ps1`)부터 Windows 가 모르는 프록시가 필요하면 `irm` 에도 `-Proxy http://proxy:3128
  -ProxyUseDefaultCredentials` 를 붙입니다 — 서버 화면은 프록시를 넣으면 이렇게 만들어 줍니다.

설치되는 것:

| 위치 | 무엇 | 권한 |
|---|---|---|
| `C:\Program Files\VEXPLOR Edge\vexplor-edge.exe` | 프로그램(실행 파일 하나) | 관리자만 쓰기, 누구나 읽기 |
| `C:\Program Files\VEXPLOR Edge\vexplor-edge-service.exe` · `.xml` | 서비스 래퍼 WinSW 2.12.0(MIT)과 그 설정 | 위와 같음 |
| `C:\ProgramData\VEXPLOR Edge\edge.json` | 설정(UTF-8, BOM 없음) | SYSTEM · 관리자 쓰기, 서비스는 읽기 |
| `C:\ProgramData\VEXPLOR Edge\state\` | 키(`identity.json`) · 대기열 · 거부된 묶음 · OPC UA 인증서 | SYSTEM · 관리자 · 서비스만 |
| `C:\ProgramData\VEXPLOR Edge\logs\` | `vexplor-edge-service.out.log`(수집기 JSON 줄)와 래퍼 기록, 10 MB 마다 넘기고 8개 보관 | 위와 같음 |
| 서비스 `vexplor-edge`(「VEXPLOR Edge」) | 계정 `NT AUTHORITY\LocalService`, 자동(지연) 시작, 멈추면 10초 뒤 다시 시작(세 번째부터 60초), Ctrl+C 로 정지 | — |

**래퍼를 쓰는 까닭.** Node.js 는 Windows 서비스 관리자에 응답하지 못합니다 — `sc.exe` 로 실행 파일만 등록하면 30초 뒤에
끝납니다(오류 1053). 작은 네이티브 래퍼가 필요하고, WinSW 는 MIT 라이선스의 파일 하나이며 내려받은 파일을
`scripts/pack.mjs` 가 SHA-256 으로 고정해 대조합니다. 라이선스 전문은 꾸러미의 `licenses/WinSW-LICENSE.txt` 에 있습니다. 계정 ·
시작 방식 · 다시 시작 규칙은 `install.ps1` 이 서비스 관리자(CIM · `sc.exe`)로 직접 정합니다.

**운영.** `Get-Service vexplor-edge` · `Restart-Service vexplor-edge`(설정을 바꾼 뒤) ·
`Get-Content -Wait "C:\ProgramData\VEXPLOR Edge\logs\vexplor-edge-service.out.log"` ·
`& "C:\Program Files\VEXPLOR Edge\vexplor-edge.exe" --version`.

**직접 설치(인터넷이 막힌 PC).** 다른 PC 에서 Releases 의 `vexplor-edge-<판>-win-x64.zip` 과 `SHA256SUMS` 를 받아 옮긴 뒤
관리자 PowerShell 에서:

```powershell
(Get-FileHash .\vexplor-edge-<판>-win-x64.zip -Algorithm SHA256).Hash   # SHA256SUMS 의 그 줄과 비교
Expand-Archive .\vexplor-edge-<판>-win-x64.zip -DestinationPath . ; cd .\vexplor-edge-<판>
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Server https://aas.example.com -Code 7KQ4-M2XD-9PRT
```

**판 올리기.** 같은 한 줄에서 `-Server … -Code …` 대신 `-Upgrade`(또는 새 꾸러미의 `install.ps1 -Upgrade`): 서비스를 멈추고
프로그램을 바꾼 뒤 다시 시작합니다. 등록 · 승인 · `edge.json` 은 그대로입니다.

## 4. 비밀번호와 인증서

- **PLC 비밀번호**는 이 PC 의 자격 증명 파일에 엔드포인트별로 둡니다 — `{ "opc.tcp://10.0.0.5:4840": { "userName",
  "password" } }`, `--credentials-file` 로 넘깁니다. AAS 와 읽을 목록에는 들어가지 않습니다. MQTT 브로커 로그인도 같은
  파일에 그 브로커 주소로 둡니다(1.1.0 이상).
- **OPC UA 인증서**: 수집기는 `<상태>/opcua-pki` 에 자기 인증서를 만듭니다. 처음 보는 서버 인증서는 거절하고
  `<상태>/opcua-pki/rejected` 에 두며, `trusted/certs` 로 옮기면 신뢰합니다(또는 `"opcua": { "trustFirstUse": true }`).
  OPC UA 서버도 수집기 인증서를 신뢰해야 합니다.

## 5. 운영

- 끊겨도 잃지 않습니다: 묶음은 `<상태>/queue` 에서 기다리다 서버가 다시 답하면 순서대로 나갑니다(각 묶음은 한 번만 저장).
  `maxQueuedBatches`(기본 100 000)를 넘거나 `maxQueueDays`(기본 30일)보다 오래되면 가장 오래된 것부터 버리고 그 수를
  보고합니다 — 알리지 않고 버리는 일은 없습니다.
- **바뀐 값만 보내기(OPC UA)**: `"opcua": { "mode": "subscribe" }` 로 두면 PLC 가 태그마다 정한 주기로 값을 살피고, 바뀌었을
  때만 보냅니다. `"deadband": <숫자>` 를 주면 아날로그(실수) 태그에서 그보다 작은 변화는 보내지 않습니다 — 카운터 · 상태 ·
  글자 태그에는 적용하지 않습니다. 값이 그대로여도 `"resendMs"`(기본 300 000, 5분)마다 다시 보내 「받는 중」으로
  보이게 합니다. 실측(PLC 모의기, 태그 6개 · 1초 · 5분): 매번 읽기 1 794개(283 KB) → 구독 729개(130 KB, −54%) → 구독 +
  불감대 1.0 436개(88 KB, −69%). 기본은 지금처럼 `"poll"` 입니다.
- 서버가 형식 오류로 거절한 묶음은 사람이 볼 수 있게 `<상태>/refused` 로 옮깁니다.
- 해지된 장치는 스스로 보내기를 멈추고 대기열을 지킵니다. 스스로 다시 등록하지 않습니다.
- 새 판 알림(선택): `"update": { "manifestUrl": "https://…", "publicKey": "<릴리스 키>" }` 를 두면 서명이 맞는 새 판을
  기록과 다음 묶음의 상태에 알립니다. 내려받거나 설치하지 않습니다 — 새 꾸러미를 같은 설치 명령으로 설치하십시오.

## 6. 제거

Linux: `sudo systemctl disable --now vexplor-edge && sudo rm -r /opt/vexplor-edge /etc/vexplor-edge /etc/systemd/system/vexplor-edge.service`
(대기열이 더 필요 없으면 `/var/lib/vexplor-edge` 도).

Windows: 한 줄 명령에서 `-Server … -Code …` 대신 `-Uninstall`, 또는 관리자 PowerShell 에서
`powershell -ExecutionPolicy Bypass -File "C:\Program Files\VEXPLOR Edge\install.ps1" -Uninstall`. 서비스와 프로그램을 지우고
`C:\ProgramData\VEXPLOR Edge` 는 남깁니다. `-Purge` 를 붙이면 그것(키 · 대기열)까지 지웁니다.

서버에서도 장치를 해지하십시오.

## 7. 확인한 것

- **원클릭(2026-10-18, 1.0.0)** — 서버 화면이 만든 명령을 그대로 깨끗한 Ubuntu 24.04 컨테이너(arm64 · x86_64 각각)에서 실행해
  릴리스 내려받기 → `SHA256SUMS` 대조 → 설치 → 미리 승인된 등록 → OPC UA 가상 PLC 읽기 → 서버 저장까지 확인했습니다(arm64 값 21개 ·
  x86_64 값 70개, 설비 연결 정상). 컨테이너에는 systemd 가 없어 `--no-service` 로 실행했습니다.
- **서비스(이전 판 — AAS Studio 2.4 시기 같은 설치기)** — 깨끗한 Ubuntu 24.04(x86_64) 실기에 설치해 systemd 서비스로 등록 · 승인 ·
  네트워크 너머 OPC UA 서버 값 송신까지 확인했습니다.
- **Windows(1.2.0)** — 바뀔 때마다 Windows Server 실행기(`windows-latest`, 작업 `windows`)의 CI 가 확인합니다: Windows 파일
  시스템에서 단위 시험, 그 자리에서 꾸러미 만들기, Windows PowerShell 5.1 로 스크립트 구문 확인, 실행 파일 `--version`, 그리고
  대역 서버를 상대로 꾸러미를 실제 서비스로 설치 — LocalService 로 실행, 대기열 쓰기와 보내기, 프로그램을 강제로 끝낸 뒤 다시 시작,
  서비스와 함께 정지, 판 올리기, 제거(`test/windows/service-smoke.ps1`). 공장 PC 설치는 아직입니다.
