# VEXPLOR Edge 사용법

*English: [usage.md](usage.md)* · 설치 요약: [설치.md](설치.md) · 규격: [계약.md](계약.md)

VEXPLOR Edge 는 공장 PC 한 대에 두는 원격 수집기입니다. 서버에서 사람이 승인한 목록의 설비 값만 읽어 HTTPS 로 밖으로
보냅니다. 이 문서는 처음 연결부터 운영 · 문제 해결 · 제거까지 화면과 명령을 순서대로 보여 줍니다. 화면은 VEXPLOR AAS
Studio 2.7.0, 수집기는 VEXPLOR Edge 1.0.1 기준이고, 모든 캡처는 실제 서버 · 실제 수집기(1.0.0) · 가상 PLC 로 찍었습니다
(2026-10-18).

## 1. VEXPLOR Edge 는 무엇인가

AAS Studio 서버가 설비와 같은 망에 있으면 서버 안의 수집기가 직접 PLC 를 읽습니다. 서버가 공장 밖(클라우드 · 본사)에
있으면 서버는 공장 안 PLC 에 닿지 못합니다. 이때 공장 PC 한 대에 VEXPLOR Edge 를 두면, 그 PC 가 PLC 를 읽어 서버로
보냅니다.

### 1-1. 먼저 알아 둘 것 하나 — 설비에 닿는 쪽만 값을 읽습니다

PLC 같은 설비는 보통 공장 안 네트워크(공장 안 컴퓨터끼리 서로 닿는 범위)에만 연결돼 있습니다. 밖에서는 그 설비에
닿을 수 없습니다. 그래서 **설비 값을 읽는 프로그램은 설비와 같은 네트워크에 있어야 합니다.**

AAS Studio 서버를 어디에 두느냐에 따라 경우가 셋으로 나뉩니다.

| 경우 | 서버 위치 | 설비 값은 누가 읽나 | VEXPLOR Edge |
|---|---|---|---|
| A | 공장 안 | 서버가 직접 | 필요 없음 |
| B | 공장 밖(클라우드 · 본사) | 공장 PC 에 둔 VEXPLOR Edge | **필요** |
| C | 공장 밖 + VPN 으로 공장 네트워크와 연결 | 서버가 VPN 을 거쳐 직접 | 없어도 됨 |

### 1-2. 그림으로 보는 세 가지 경우

**경우 A — 서버가 공장 안에 있을 때**

```mermaid
flowchart LR
  subgraph F["공장 안 네트워크"]
    PLC["설비(PLC)"] -- "값" --> SRV["AAS Studio 서버"]
    PC["담당자 PC<br/>(브라우저)"] -- "화면 사용" --> SRV
  end
```

서버와 설비가 같은 네트워크에 있어 서버가 설비 값을 직접 읽습니다. 화면의 모든 기능이 됩니다. VEXPLOR Edge 는
쓰지 않습니다.

**경우 B — 서버가 공장 밖에 있을 때 (VEXPLOR Edge 사용)**

```mermaid
flowchart LR
  subgraph F["공장 안 네트워크"]
    PLC["설비(PLC)"] -- "값을 읽음" --> EDGE["공장 PC<br/>VEXPLOR Edge"]
  end
  subgraph C["공장 밖 (클라우드 · 본사)"]
    SRV["AAS Studio 서버"]
  end
  EDGE -- "밖으로만 보냄<br/>(인터넷 HTTPS)" --> SRV
```

서버는 공장 안 설비에 닿지 못합니다(밖에서 공장 안으로 들어가는 길이 없습니다). 대신 공장 PC 한 대에 VEXPLOR Edge 를 두면, 그 PC 가 설비 값을 읽어 서버로
보냅니다. 공장 쪽에서는 **밖으로 나가는 길만** 있으면 되고, 밖에서 공장 안으로 들어오는 길은 열지 않습니다.

이 경우 **서버가 직접 설비에 붙는 기능은 쓰지 못합니다.**

- 「설비에서 불러오기」(설비의 태그 목록을 훑어 와서 고르는 단추)가 안 됩니다. 태그 주소를 손으로 적거나 패턴으로
  여러 개를 한 번에 적습니다. 태그 주소는 PLC 제조사의 태그 목록에서 확인합니다.
- 「수집」(지금 한 번 읽기) 단추는 「접속 실패」가 나옵니다. 누르지 않아도 VEXPLOR Edge 가 보낸 값이 저절로 들어옵니다.

태그를 손으로 적기 어렵다면 **설정할 때만** 공장 안 노트북에서 AAS Studio 를 잠깐 띄워 「설비에서 불러오기」로 수집
연결을 만들고, 그 설비 파일(AASX)을 「AASX 내려받기」로 저장한 뒤 공장 밖 서버에 「AASX 파일 열기」로 올리면 됩니다.

**경우 C — 서버가 공장 밖이지만 VPN 으로 공장 네트워크와 연결했을 때**

```mermaid
flowchart LR
  subgraph F["공장 안 네트워크"]
    PLC["설비(PLC)"] --- VF["VPN 장비"]
  end
  subgraph C["공장 밖 (클라우드 · 본사)"]
    VC["VPN 장비"] --- SRV["AAS Studio 서버"]
  end
  VF <== "VPN 전용 통로" ==> VC
```

VPN 은 공장 네트워크와 서버 쪽 네트워크 사이에 놓는 전용 통로입니다. 이 통로가 있으면 서버가 공장 안 설비에
닿으므로, 경우 A 처럼 서버가 직접 읽고 「설비에서 불러오기」도 됩니다. VEXPLOR Edge 는 없어도 됩니다.

다만 알아 둘 점이 있습니다.

- **서버 쪽 네트워크와 공장 네트워크를 연결하는 VPN 이어야 합니다**(사이트 간 VPN). 담당자 노트북 한 대만 공장에 접속하는
  VPN 으로는 서버가 설비에 닿지 못합니다.
- 밖에서 공장 안으로 들어오는 길을 여는 일이라 **회사 보안 담당의 승인**이 필요한 경우가 많습니다. VPN 장비를 두고
  관리하는 일도 따로 생깁니다.
- VPN 이 끊긴 동안은 서버가 값을 읽지 못하고, 그동안의 값은 남지 않습니다. 경우 B 의 VEXPLOR Edge 는 끊긴 동안 공장
  PC 에 값을 쌓아 두었다가 다시 연결되면 보냅니다(14절).

### 1-3. 경우마다 되는 일

| 하는 일 | A 공장 안 서버 | B 밖 서버 + VEXPLOR Edge | C 밖 서버 + VPN |
|---|---|---|---|
| 설비 값 모으기 | 됨 | 됨 | 됨 |
| 「설비에서 불러오기」로 태그 고르기 | 됨 | **안 됨** — 손으로 적거나, 공장 안에서 만든 파일을 올림 | 됨 |
| 「수집」 단추로 지금 한 번 읽기 | 됨 | **안 됨** — 값은 저절로 들어옴 | 됨 |
| 인터넷 · VPN 이 끊긴 동안의 값 | 해당 없음 | 공장 PC 에 쌓았다가 나중에 보냄 | 남지 않음 |
| 공장 안으로 들어오는 길 열기 | 필요 없음 | 필요 없음 | **필요**(VPN) |
| 공장에 둘 것 | 서버 | Linux PC 한 대 | VPN 장비 |

### 1-4. 어느 경우를 고를까

- 서버를 공장 안에 둘 수 있으면 **경우 A** 가 가장 간단합니다.
- 서버가 클라우드나 본사에 있고, 공장 네트워크로 들어오는 길을 열기 어려우면 **경우 B(VEXPLOR Edge)** 를 고릅니다.
  이 문서의 나머지는 경우 B 를 설명합니다.
- 이미 공장과 본사가 VPN 으로 연결돼 있으면 **경우 C** 도 됩니다. VEXPLOR Edge 없이 서버가 직접 읽습니다.

수집기가 무엇을 읽을지는 공장 PC 에서 정하지 않습니다(3절). 서버의 설비 파일(AASX)에 들어 있는 수집 연결(AID)이 「읽을
목록」이 되고, 사람이 서버 화면에서 그 목록을 승인해야 수집기가 읽기 시작합니다.

## 2. 준비물

**서버**

| 항목 | 내용 |
|---|---|
| VEXPLOR AAS Studio | 2.7.0 이상(원클릭 화면). 2.3.0 ~ 2.6.x 서버도 규격 `vexplor.edge/1` 로 받지만, 연결은 API 와 수동 설치로 합니다 |
| 주소 | 공장 PC 가 찾아올 수 있는 **https** 주소. 수집기는 https 가 아닌 서버에 붙지 않습니다(같은 PC 안 시험만 예외). 서버 앞에 HTTPS 를 두는 법은 AAS Studio 사용법 12-3절 |
| 읽을 목록 | 설비 파일에 수집 연결(AID)이 하나 이상. 없으면 연결은 되지만 읽을 것이 없습니다(4-2절) |
| 계정 | 원격 수집을 켜는 일은 관리자, 명령을 만들고 승인하는 일은 편집 권한 계정 |

**공장 PC**

| 항목 | 내용 |
|---|---|
| 운영체제 | Linux x64 또는 arm64, systemd. Windows 판은 준비 중입니다 — 그때까지는 Linux PC 나 Windows 서버 위의 Linux VM 을 사용합니다 |
| 도구 | `curl`, `sha256sum`(또는 `shasum`), 관리자 권한(`sudo`). Node.js 는 필요 없습니다 — 실행 파일 하나에 모두 들어 있습니다 |
| 내려받는 크기 | 꾸러미 약 44 MB(1.0.0 기준) |
| 나가는 길 | 서버 주소 443 으로 나가는 길(직접 또는 현장 프록시) |
| 설비 쪽 | PLC 포트에 닿는 길 — OPC UA 4840, Modbus TCP 502, MQTT 1883/8883 |
| 들어오는 길 | **필요 없습니다.** 수집기는 포트를 열지 않습니다 |

PC 를 어디에 둘지는 [설치.md](설치.md) 1절(DMZ · 사무망 / 설비망 두 가지 배치)을 참고합니다.

## 3. 설비 연결과 값 수집 — 무엇을 어디서 정하고 어떻게 읽나

VEXPLOR Edge 는 공장 PC 에서 설비에 붙어 값을 읽고 보내기만 합니다. **PLC 번지 · 레지스터 종류 · 자료형 · 태그 이름 같은
수집 내용은 공장 PC 에서 정하지 않고, AAS Studio 의 설비 파일에 들어 있는 수집 연결(AID)에서 정합니다.** 공장 PC 의
`edge.json` 에는 서버 주소 · 프록시 · 인증서 · PLC 비밀번호 파일처럼 그 PC 에만 있어야 하는 것과 OPC UA 수집 방식만
둡니다. 이 절은 무엇을 어디서 정하는지, 값이 설비에서 서버 화면까지 어떻게 가는지를 실제 예로 보여 줍니다.

### 3-1. 무엇을 어디서 정하나

| 정할 것 | 정하는 곳 | 어떻게 |
|---|---|---|
| 설비 주소(접속 주소) | AAS Studio — 수집 연결 | 「수집 연결 만들기」의 ① 칸. **공장 PC 에서 닿는 주소**를 적습니다(3-4절) |
| 통신 방식 | AAS Studio — 수집 연결 | 주소 앞부분으로 정해집니다. `opc.tcp://` 는 OPC UA, `modbus+tcp://` 는 Modbus TCP, `mqtt://` · `mqtts://` 는 MQTT |
| 태그 주소(PLC 번지) | AAS Studio — 수집 연결 | 줄마다 적습니다. OPC UA 는 NodeId, Modbus 는 레지스터 번호, MQTT 는 토픽(3-3절) |
| Modbus 레지스터 종류 | AAS Studio — 수집 연결 | 줄마다 목록에서 고릅니다 — 보유 레지스터 · 입력 레지스터 · 코일 · 입력 비트 |
| Modbus 관례 주소(`40001` 등) | AAS Studio — 수집 연결 | 주소 칸에 `40001` 을 넣으면 옆에 「40001 → 보유 레지스터 0번」 단추가 나옵니다. 눌러야 바뀝니다 |
| Modbus 읽을 레지스터 수(quantity) | AAS Studio — 수집 연결 | 자료형에 따라 저절로 정해집니다(1 · 2 · 4개). 다르게 읽어야 하면 주소 뒤에 `?quantity=2` |
| 자료형 | AAS Studio — 수집 연결 | Modbus 는 unsignedShort · short · unsignedInt · int · float · double · boolean, OPC UA · MQTT 는 float · integer · string · boolean 에서 고릅니다 |
| Modbus 바이트 · 워드 순서 | AAS Studio — 수집 연결(API) | 기본은 상위 바이트 먼저, 상위 워드 먼저입니다. 화면에는 바꾸는 칸이 없습니다(3-3절) |
| 단위 | AAS Studio — 수집 연결(API) | 화면에는 칸이 없습니다. API 로 만들거나 단위가 적힌 AID 를 가져온 경우에만 목록에 실립니다 |
| 태그 이름 | AAS Studio — 수집 연결 | 설비 모델의 요소 이름(idShort)과 같게 짓습니다. 그래야 표준 API 로 그 요소 자리에 값이 나갑니다 |
| 읽는 주기 | AAS Studio 서버 | 기본 5초. 서버를 `COLLECT=on` · `COLLECT_INTERVAL=<초>` 로 띄웠으면 그 값입니다. 설비 · 태그마다 다르게 하려면 승인 API 의 `intervals`(100ms ~ 1시간, [계약.md](계약.md) 8절). 화면의 승인 단추는 기본값으로 승인합니다 |
| OPC UA 보안 방식(Sign · SignAndEncrypt) · 사용자 이름 로그인 | AAS Studio — 수집 연결 | AID 에 보안 정의(`securityDefinitions`)가 적혀 있어야 합니다. 화면으로 만든 수집 연결에는 보안 정의가 없어 **보안 None · 익명**으로 붙습니다 |
| PLC 사용자 이름 · 비밀번호 | 이름표는 서버, 실제 값은 공장 PC | 서버는 읽을 목록에 이름표(`credentialRef` = 그 설비의 접속 주소)만 넣고, 실제 값은 공장 PC 의 `credentials.json` 에 둡니다(12-3절). OPC UA 만 해당합니다 |
| MQTT 사용자 이름 · 비밀번호 | AAS Studio — 수집 연결 | 주소 안에 적습니다(`mqtt://사용자:암호@호스트:1883`). 그래서 서버의 설비 파일에 남습니다(3-9절) |
| 수집 방식(매번 읽기 · OPC UA 구독), 불감대, 다시 보내는 간격 | 공장 PC — `edge.json` | `opcua.mode` · `opcua.deadband` · `opcua.resendMs`(13절) |
| 묶음 간격 · 대기열 크기 | 공장 PC — `edge.json` | `flushIntervalMs` · `maxQueuedBatches` · `maxQueueDays`(11절) |
| 서버 주소 · 프록시 · 사설 인증서 · OPC UA 인증서 | 공장 PC — `edge.json` | 11절 · 12절 |

**제조사 전용 통신은 없습니다.** LS XGT 의 FEnet 처럼 제조사마다 다른 방식은 읽지 못합니다. PLC 나 통신 모듈의
**Modbus TCP 서버**나 **OPC UA 서버**를 켜서 그 주소로 연결합니다. 서버의 읽을 목록에는 HTTP 설비도 실릴 수 있지만,
VEXPLOR Edge 1.0.1 은 OPC UA · Modbus TCP · MQTT 만 읽습니다(HTTP 설비는
「설비 연결 오류: HTTP is not read by this edge yet」).

### 3-2. 한 바퀴 — 설비 파일에서 서버 화면까지

```mermaid
flowchart LR
  AID["AAS Studio<br/>설비 파일의 수집 연결(AID)<br/>주소 · 번지 · 자료형"] -- "서버가 바꿈" --> LIST["읽을 목록<br/>주소 · 태그 · 주기"]
  PERSON["사람"] -- 승인 --> LIST
  LIST -- "60초마다 물어봄<br/>(승인 대기 중 10초)" --> EDGE["공장 PC<br/>VEXPLOR Edge"]
  EDGE -- "주기마다 읽기만" --> PLC["PLC · 제어기"]
  EDGE -- "5초마다 서명한 묶음<br/>(먼저 디스크에 쌓음)" --> SERVER["AAS Studio 서버<br/>확인 · 저장"]
  SERVER --> OUT["「수집」 칸 · REST 현재값<br/>OPC UA 내주기 · MES · ERP 연동"]
```

1. 사람이 AAS Studio 에서 설비 파일에 수집 연결(AID)을 만듭니다 — 설비 주소와 읽을 태그를 적습니다
2. 서버는 그 작업 공간이 가진 설비 파일의 수집 연결을 모아 「읽을 목록」으로 바꿉니다. 목록에는 주소와 번지만 있고
   비밀번호는 없습니다
3. 사람이 그 목록을 승인합니다(6절)
4. 수집기가 승인된 목록을 받아 설비에 붙고, 정해진 주기로 읽습니다
5. 읽은 값을 묶어 서명한 뒤 서버로 보내고, 서버는 승인한 태그인지 확인한 뒤 저장합니다
6. 값은 설비 파일의 「수집」 칸에 보이고, 서버 안 수집기로 받은 값과 똑같이 밖으로 나갑니다

### 3-3. 통신 방식별 주소와 태그 적는 법

설비 파일을 열고 오른쪽 「← 수집 — 설비에서 받아 오기」에서 **「수집 연결 만들기」** 를 누릅니다. ① 칸에 설비의 접속
주소를 넣고, 태그는 **「+ 손으로 입력」** 으로 한 줄씩 넣거나 **「+ 패턴으로 여러 개」** 로 번호만 다른 태그를 한 번에
넣습니다. OPC UA 는 **「설비에서 불러오기」** 로 설비의 태그 목록을 훑어 올 수도 있습니다 — 다만 이 단추는 서버가 직접
설비에 붙으므로, 서버가 공장 밖이면 쓰지 못합니다(3-4절). 다 넣었으면 **「만들기」** 를 누릅니다. 화면 사용법 전체는
AAS Studio 사용법 [8-1절 수집 연결 만들기](https://github.com/waceinc/vexplor-aas/blob/main/docs/사용법.md#8-1-수집-연결-만들기)에
있습니다.

**OPC UA**

| 적는 곳 | 형식 | 예 |
|---|---|---|
| 접속 주소 | `opc.tcp://호스트:포트[/경로]` | `opc.tcp://192.168.10.21:4840` |
| 태그 주소 | NodeId | `ns=1;s=Machine.MotorSpeed` · `ns=2;i=1005` |
| 자료형 | float · integer · string · boolean | 실수는 float, 카운터는 integer |

한 설비의 태그는 한 번의 요청으로 함께 읽습니다. 장비가 값에 붙여 준 시각을 그대로 쓰고, 장비가 아직 값이 없다고
답한 태그(`BadWaitingForInitialData` 등)는 보내지 않습니다. 그 밖의 나쁜 상태는 빈 값과 상태 이름(예:
`BadNodeIdUnknown`)을 보냅니다.

**Modbus TCP**

| 적는 곳 | 형식 | 예 |
|---|---|---|
| 접속 주소 | `modbus+tcp://호스트:포트/unitID` — 포트를 빼면 502, unitID 를 빼면 1 | `modbus+tcp://192.168.10.30:502/1` |
| 태그 주소 | 레지스터 번호(0부터 시작하는 번호). `1/40` 처럼 앞에 unitID 를 붙일 수 있고, 뒤에 `?quantity=n` 을 붙이면 n개를 읽습니다 | `40` · `1/40` · `1/40?quantity=2` |
| 레지스터 종류 | 보유 레지스터 · 입력 레지스터 · 코일 · 입력 비트 | 줄마다 목록에서 고릅니다. 기본은 보유 레지스터 |
| 자료형 | 아래 표 | 줄마다 목록에서 고릅니다. 기본은 unsignedShort |

| 자료형 | 읽는 레지스터 수 | 값 |
|---|---|---|
| unsignedShort · short | 1 | 0 ~ 65535 · −32768 ~ 32767 |
| unsignedInt · int · float | 2 | 32비트 정수 · 32비트 실수 |
| double | 4 | 64비트 실수 |
| boolean | 1 | 레지스터는 0 이 아니면 true. 코일 · 입력 비트는 그 비트 값 |

- **관례 주소.** PLC 설명서의 `40001` · `30010` · `00005` · `10003` 처럼 앞자리가 종류인 주소는 그대로 넣으면 안 됩니다.
  주소 칸에 넣으면 옆에 「40001 → 보유 레지스터 0번」 같은 단추가 나오고, 누르면 종류와 0부터 시작하는 번호로 바뀝니다.
  누르지 않으면 `40001` 을 레지스터 번호 그대로 읽습니다 — 엉뚱한 레지스터를 읽거나, 그 번호가 없는 장치면 빈 값이 됩니다(3-8절에서 실측)
- **바이트 · 워드 순서.** 기본은 상위 바이트 먼저, 상위 워드 먼저(빅 엔디언)입니다. float · 32비트 정수가 엉뚱한 값으로
  보이면 PLC 가 하위 워드를 먼저 보내는 경우입니다. 화면에는 이를 바꾸는 칸이 없으므로, AAS Studio API
  `POST /packages/{id}/aid` 로 태그마다 `"form": { "modv_mostSignificantWord": "false" }` 를 넣어 수집 연결을 만듭니다
  (같은 방법으로 `"unit"` 도 넣을 수 있습니다)

**MQTT**

| 적는 곳 | 형식 | 예 |
|---|---|---|
| 접속 주소 | `mqtt://[사용자:암호@]호스트:포트` — 포트를 빼면 1883, `mqtts://` 는 TLS 이고 8883 | `mqtt://broker.plant.local:1883` |
| 태그 주소 | 토픽(`+` · `#` 같은 와일드카드 없이) | `plant/press1/temp` |
| 자료형 | float · integer · string · boolean | |

MQTT 는 수집기가 묻지 않고 장치가 보내 줍니다. 수집기는 연결할 때 토픽을 구독해 두고, 주기마다 **그 토픽에서 마지막으로 받은
값**을 담습니다. 아직 한 번도 오지 않은 토픽은 보내지 않습니다. 메시지 본문에서 값을 꺼내는 규칙은 다음과 같습니다.

| 본문 | 담기는 값 |
|---|---|
| `61.2` · `true` | 숫자 · 참거짓 그대로 |
| `{"value": 61.2}` | `value` 의 값 |
| `RUN` 처럼 JSON 이 아닌 글자 | 글자 그대로 |
| `{"temp": 61.2}` 처럼 `value` 가 없는 JSON | 본문 글자 전체. 자료형이 float · integer 면 서버가 받지 않습니다(`TypeMismatch`) |

### 3-4. 설비 주소는 공장 PC 기준입니다 — 서버가 공장 밖일 때

서버 위치에 따라 무엇이 되고 안 되는지는 [1-2절 그림](#1-2-그림으로-보는-세-가지-경우)과 1-3절 표에 먼저 정리해 두었습니다. 이 절은 설치 담당자를 위한 자세한 설명입니다.

수집기는 읽을 목록의 주소로 **공장 PC 에서 직접** 붙습니다. 그래서 수집 연결의 주소에는 서버에서 보이는 주소가 아니라
공장 PC 에서 닿는 주소를 적습니다. 보통은 `192.168.x.x` 같은 공장 안 사설 주소 그대로입니다.

서버가 클라우드 · 본사에 있으면 AAS Studio 화면의 두 단추가 그 주소에 닿지 못합니다. 둘 다 **서버가 직접** 설비에 붙는
단추이기 때문입니다.

| 단추 | 서버가 공장 밖일 때 | 대신 할 일 |
|---|---|---|
| 「설비에서 불러오기」(OPC UA 태그 훑기) | 서버가 공장 안 주소에 붙지 못해 오류가 납니다. 수집기를 거치지 않습니다 | 「+ 손으로 입력」 · 「+ 패턴으로 여러 개」로 NodeId 를 적습니다. NodeId 는 PLC 제조사의 태그 목록이나, 공장 안 PC 의 OPC UA 클라이언트 프로그램으로 확인합니다. 공장 망 안에서 AAS Studio 를 따로 띄울 수 있으면 거기서 불러오기로 수집 연결을 만든 뒤, 그 설비 파일(AASX)을 서버에 올려도 됩니다 |
| 「수집」(지금 한 번 읽기) | 「접속 실패」가 나옵니다 | 누르지 않아도 됩니다. 원격 수집기가 보낸 값은 저절로 「수집」 칸에 들어옵니다(7절) |

서버를 `COLLECT=on` · `COLLECT_INTERVAL` 로 띄워 서버 자신도 자동 수집을 하면, 서버가 그 주소를 읽지 못해 「수집」 칸에
「접속 실패 (자동)」이 나옵니다. 이 표시는 원격 수집기의 「받는 중」보다 먼저 보이므로, 원격 수집기만 쓰는 서버에서는
`COLLECT_INTERVAL` 을 두지 않는 편이 낫습니다. 읽는 주기는 승인 API 의 `intervals` 로 정할 수 있습니다(3-1절).

### 3-5. 승인한 뒤 수집기가 하는 일

1. **목록 받기.** 시작할 때 읽을 목록을 받고, 그 뒤 60초마다 다시 묻습니다(승인을 기다리는 동안에는 10초마다). 목록이
   그대로면 서버는 바뀌지 않았다는 답(304)만 답합니다. 묶음을 보낼 때 서버가 알려 준 목록 판이 다르면 60초를 기다리지 않고
   바로 다시 받습니다. 목록이 바뀌면 설비 연결을 모두 닫고 새 목록으로 다시 엽니다
2. **설비에 붙기.** 설비(수집 연결)마다 연결을 하나 엽니다. OPC UA 는 목록을 받는 순간 접속하고(5초 안에 안 되면
   실패), Modbus TCP 는 처음 읽을 때 접속하며, MQTT 는 브로커에 붙어 토픽을 구독합니다
3. **주기마다 읽기.** 같은 주기의 태그를 묶어 함께 읽습니다. 앞 회차 읽기가 아직 안 끝났으면 그 회차는 건너뜁니다.
   `edge.json` 에서 `opcua.mode` 를 `"subscribe"` 로 두면 OPC UA 는 읽지 않고 바뀐 값만 받습니다(13절)
4. **값 담기.** 태그마다 태그 번호 · 값 · 품질 · 장비 시각 · 받은 시각을 담습니다. 장비 시각은 OPC UA 면 장비가 준 시각,
   MQTT 면 메시지를 받은 시각, Modbus 면 읽은 시각입니다. 값이 아직 없는 태그는 담지 않고, 못 읽은 태그는 빈 값으로 담습니다
   — 수집기는 값을 지어내지 않습니다
5. **묶어서 보내기.** 5초마다(`flushIntervalMs`) 모은 값을 묶음 하나로 만들어 먼저 공장 PC 디스크에 저장합니다. 묶음 하나에는
   값이 5,000개까지 들어갑니다. 그다음 오래된 묶음부터 차례로 이 PC 의 키로 서명해 HTTPS 로 보내고, 서버가 받았다고 답한
   묶음만 지웁니다. 값이 없어도 1분에 한 번은 빈 묶음을 보내 살아 있음을 알립니다. 통신이 끊겼을 때는 14절

### 3-6. 서버가 받은 뒤

- **확인.** 서명이 맞는지, 값마다 승인한 목록의 태그인지, 자료형이 맞는지(float · integer 태그에 글자가 오면
  `TypeMismatch`) 봅니다. 맞지 않는 값만 빼고 나머지를 받으며, 같은 묶음이 두 번 와도 한 번만 저장합니다
- **저장.** 값은 설비 파일(AASX)에 되쓰지 않고 서버의 값 저장소에 쌓입니다. 설비 파일 · 수집 연결 · 태그 이름 · 주소와 함께
  저장되므로, 서버 안 수집기가 읽은 값과 같은 자리에 들어갑니다
- **화면.** 설비 파일의 「수집」 칸에 최근 값과 시각이 보이고, 최근 3분 안에 값이 왔으면 「받는 중」이 붙습니다(7절).
  원격 수집기 창에는 마지막 수신 · 받은 값 수 · 설비 연결 상태가 보입니다(8절)
- **다른 시스템으로.** 서버 안 수집기 값과 똑같이 나갑니다.

| 가져가는 방법 | 안내 |
|---|---|
| 표준 API 에 현재값을 얹어 읽기(`?live=true`) | AAS Studio 사용법 [8-5절](https://github.com/waceinc/vexplor-aas/blob/main/docs/사용법.md#8-5-다른-시스템에-현재값-내보내기-rest) |
| AAS Studio 가 OPC UA 서버가 되어 내주기 | AAS Studio 사용법 [8-6절](https://github.com/waceinc/vexplor-aas/blob/main/docs/사용법.md#8-6-값-내주기--이-도구가-opc-ua-서버가-됩니다) |
| MES · ERP · CMMS 로 상태 · 알람 · 계수 사건 보내기 | AAS Studio 사용법 [8-7절](https://github.com/waceinc/vexplor-aas/blob/main/docs/사용법.md#8-7-mes--erp--cmms-연동) |

### 3-7. 예 1 — 프레스 1호기, OPC UA 태그 3개

프레스 1호기 PLC 의 OPC UA 서버가 공장 안 `opc.tcp://192.168.10.21:4840` 에 있고, 모터 속도 · 생산 수량 · 알람 세 값을
받는다고 합시다.

1. **수집 연결 만들기.** 서버에서 프레스 1호기 설비 파일을 열고 「수집 연결 만들기」. ① 칸에 `opc.tcp://192.168.10.21:4840`.
   서버가 공장 밖이므로 「설비에서 불러오기」 대신 「+ 손으로 입력」으로 세 줄을 넣고 「만들기」를 누릅니다

   | 이름 | NodeId | 자료형 |
   |---|---|---|
   | MotorSpeed | `ns=1;s=Machine.MotorSpeed` | float |
   | CycleCount | `ns=1;s=Machine.CycleCount` | integer |
   | AlarmActive | `ns=1;s=Machine.AlarmActive` | boolean |

2. **연결 명령.** 「설정 ▾ → 원격 수집기 (VEXPLOR Edge)」 → 「+ 수집기 연결」. 목록에 이 설비 · OPC UA · 태그 3개가
   보이는지 확인하고, 「이 목록을 바로 읽게 승인」을 켠 채 「연결 명령 만들기」(5-1절)
3. **공장 PC 에 붙여 넣기.** 「명령 복사」로 받은 한 줄을 공장 PC 터미널에 붙여 넣습니다(5-4절). 등록 기록에
   `its read list is already approved` 가 나오면 승인까지 끝난 것입니다
4. **수집기가 받는 목록.** 승인된 목록은 다음과 같습니다(비밀번호는 없고, 주기는 기본 5초)

   ```json
   { "interfaceName": "InterfaceTemplateForOPCUA", "protocol": "OPCUA",
     "endpoint": "opc.tcp://192.168.10.21:4840", "security": { "mode": "None" }, "intervalMs": 5000,
     "tags": [
       { "propertyName": "MotorSpeed",  "address": "ns=1;s=Machine.MotorSpeed",  "type": "float" },
       { "propertyName": "CycleCount",  "address": "ns=1;s=Machine.CycleCount",  "type": "integer" },
       { "propertyName": "AlarmActive", "address": "ns=1;s=Machine.AlarmActive", "type": "boolean" } ] }
   ```

5. **값 확인.** 원격 수집기 창에 「받는 중」과 「설비 연결 1/1」이 보이고, 설비 파일의 「수집」 칸에 세 값이 5초 간격으로
   들어옵니다. 공장 PC 에서는 `journalctl -u vexplor-edge` 에 `read list … (approved): 1 interface(s)` 가 남습니다

실측(2026-10-18, 이 저장소의 상호 시험 환경 — 실제 AAS Studio 서버 코드와 OPC UA 시험 서버, 주소만 `127.0.0.1`):
12초 동안 태그마다 값 2개, MotorSpeed `1200.5` · CycleCount `5200` · AlarmActive `false`, 품질 `Good`, 장비 시각과
받은 시각이 함께 저장되었습니다.

### 3-8. 예 2 — Modbus TCP

같은 설비에 Modbus TCP 로 유압 온도(보유 레지스터 10 ~ 11, float) · 생산 수량(보유 레지스터 20) · 운전 신호(코일 0)를 받는
경우입니다. ① 칸에 `modbus+tcp://192.168.10.30:502/1` 을 넣고 「+ 손으로 입력」으로 줄마다 주소 · 레지스터 종류 · 자료형을
고릅니다.

| 이름 | 주소 | 레지스터 종류 | 자료형 | 실측 값 |
|---|---|---|---|---|
| OilTemp | `10` | 보유 레지스터 | float | `23.5` |
| ProductionCount | `20` | 보유 레지스터 | unsignedShort | `1234` |
| Running | `0` | 코일 | boolean | `true` |
| (잘못된 예) | `40011` — 변환 단추를 누르지 않음 | 보유 레지스터 | unsignedShort | 빈 값(시험 장치에 40011번이 없음) |

PLC 설명서에 `40011` 로 적힌 값이라면 주소 칸에 `40011` 을 넣은 뒤 옆의 「40011 → 보유 레지스터 10번」 단추를 눌러
`10` 으로 바꿉니다. 실측은 이 저장소의 상호 시험 환경에서 AAS Studio 의 Modbus 시험 장치로 했습니다(2026-10-18).

### 3-9. 알아 둘 것

- **끊긴 설비 연결은 1.0.1 부터 저절로 다시 붙습니다.** 수집기가 목록을 받을 때 PLC 가 꺼져 있었거나, 읽는 도중 PLC ·
  MQTT 브로커가 다시 시작돼도 수집기를 다시 시작하지 않아도 됩니다. 수집기는 접속에 실패하거나 연속 3번 읽은 값이 모두
  오류이면 그 연결을 닫고 1초 뒤에 다시 엽니다. 또 실패하면 2초 · 4초 · 8초 … 로 간격을 늘리고, 간격은 60초를 넘지
  않습니다(여러 수집기가 한꺼번에 붙지 않게 간격을 조금씩 줄여 엽니다). 한 번 읽히면 간격은 다시 1초부터입니다. 끊긴
  동안 화면에는 「설비 연결 0/1」과 「설비 연결 오류: …」가 나오고, 다른 설비는 그대로 읽습니다. 읽기 주기가 5초이면
  끊긴 것을 알아채는 데 15초쯤 걸립니다. 공장 PC 기록에는 `… reconnecting in 1 s (backoff up to 60 s)` 와
  `… connected again after N attempt(s)` 가 한 줄씩 남습니다(실측 — OPC UA · Modbus TCP · MQTT, PLC 가 늦게 켜진
  경우 포함). **1.0.0 은 다시 붙지 않습니다** — 끊긴 뒤에도 「받는 중」인 채로 빈 값만 들어옵니다. PLC 나 브로커를 다시
  켰으면 공장 PC 에서 `sudo systemctl restart vexplor-edge` 를 실행합니다
- **못 읽은 이유가 화면에 남지 않는 경우가 있습니다.** OPC UA 는 빈 값에 상태 이름(`Bad…`)이 붙지만, Modbus TCP · MQTT 는
  빈 값만 보입니다. 주소 · 레지스터 종류 · 자료형 · 관례 주소 변환을 먼저 확인합니다
- **MQTT 비밀번호는 서버에 남습니다.** 접속 주소 안에 적기 때문에 설비 파일과 읽을 목록에 들어갑니다. 공장 PC 의
  `credentials.json` 은 OPC UA 에만 쓰입니다. 읽기 전용 계정을 따로 만들어 쓰십시오
- **화면으로 만든 OPC UA 수집 연결은 보안 None · 익명입니다.** `Sign` · `SignAndEncrypt` 나 사용자 이름 로그인이 필요한
  PLC 는 보안 정의가 적힌 AID 를 써야 합니다(12-3절 · 12-4절)

## 4. 서버 쪽 준비 — 원격 수집 켜기

### 4-1. 원격 수집기 창 열기

AAS Studio 머리줄 오른쪽 **「설정 ▾ → 원격 수집기 (VEXPLOR Edge)」** 를 누릅니다.

![설정 메뉴의 「원격 수집기 (VEXPLOR Edge)」](images/manual/m01-menu.png)

원격 수집이 꺼져 있으면 아래처럼 나옵니다. 관리자 계정이면 **「원격 수집 켜기」** 를 누릅니다.

![원격 수집이 꺼져 있을 때 — 「원격 수집 켜기」 단추](images/manual/m02-off.png)

켜면 「+ 수집기 연결」 단추와 연결된 수집기 목록이 나옵니다.

![원격 수집을 켠 뒤 — 「+ 수집기 연결」](images/manual/m03-on.png)

원격 수집을 켜고 끄는 방식은 서버 설정 `EDGE` 로 정합니다.

| `EDGE` 값 | 화면 |
|---|---|
| 비워 둠(기본) | 꺼진 채로 시작하고, 관리자가 이 화면에서 켭니다. 켠 상태는 서버를 다시 시작해도 유지됩니다 |
| `on` | 늘 켜짐. 화면의 켜기 단추는 나오지 않습니다 |
| `off` | 원격 수집이 없는 서버. 창에 「이 서버에는 원격 수집기가 꺼져 있습니다」가 나오고, 수집기 쪽 주소(`/edge/v1`)도 열리지 않습니다 |

체험 모드 서버와 2.7.0 보다 오래된 서버도 `off` 처럼 보입니다.

### 4-2. 읽을 목록 만들기 — 설비 파일의 수집 연결(AID)

수집기는 서버에 올라간 설비 파일의 수집 연결(AID, AssetInterfacesDescription 서브모델)을 읽습니다. 설비 파일을
열고 오른쪽 「수집」에서 **「수집 연결 만들기」** 를 누르면 만들어집니다. 주소 · 번지 · 자료형을 적는 법과 서버가 공장 밖일
때 주의할 점은 3절에, 화면 사용법 전체는 AAS Studio 사용법
[8-1절 수집 연결 만들기](https://github.com/waceinc/vexplor-aas/blob/main/docs/사용법.md#8-1-수집-연결-만들기)에 있습니다.

수집 연결이 하나도 없으면 「수집기 연결」 카드에 「읽을 태그가 아직 없습니다」가 나옵니다. 그래도 연결은 할 수 있고,
나중에 수집 연결을 만든 뒤 승인하면 됩니다.

## 5. 원클릭 연결

### 5-1. 연결 명령 만들기

**「+ 수집기 연결」** 을 누르면 카드가 열립니다. 세 가지를 확인하고 **「연결 명령 만들기」** 를 누릅니다.

![수집기 연결 카드 — 서버 주소 · 바로 승인 · 읽을 목록](images/manual/m04-card.png)

| 칸 | 내용 |
|---|---|
| 공장 PC가 찾아올 이 서버의 주소 | 지금 브라우저 주소로 미리 채워집니다. 공장 PC 에서 보이는 주소가 다르면(사내 도메인 · 공인 주소) 그 주소로 바꿉니다 |
| 이 목록을 바로 읽게 승인 | 켜 두면 이 순간의 읽을 목록을 함께 승인합니다. 공장 PC 가 연결되자마자 읽기 시작합니다(6-1절) |
| 목록 | 설비(수집 연결)마다 이름 · 통신 방식 · 태그 수 |

명령은 24시간 동안 **한 번만** 쓸 수 있습니다. 같은 명령으로 두 번째 PC 를 연결할 수 없습니다 — PC 마다 명령을 따로
만듭니다.

### 5-2. 주소를 잘못 넣으면

공장 PC 가 찾아올 수 없는 주소는 명령을 만들기 전에 걸러 냅니다.

`localhost` · `127.0.0.1` 은 이 컴퓨터 자신을 가리키므로 공장 PC 에서는 닿지 않습니다. 이때는 경고가 나옵니다.

![localhost 주소 경고](images/manual/m05-loopback.png)

`http://` 주소는 수집기가 받지 않으므로 단추가 잠깁니다.

![http 주소 — 명령을 만들 수 없음](images/manual/m05-http.png)

### 5-3. 프록시를 거치는 공장

공장 PC 가 현장 프록시로만 밖에 나갈 수 있으면 **「프록시를 거쳐야 하나요?」** 를 누르고 프록시 주소를 넣습니다.
명령에 `--proxy` 가 붙습니다. 수집기는 HTTP CONNECT 프록시를 사용합니다.

![프록시 주소 칸](images/manual/m06-proxy.png)

### 5-4. 공장 PC 에 붙여 넣기

명령이 나오면 **「명령 복사」** 를 누릅니다.

![연결 명령과 「명령 복사」 — 공장 PC 를 기다리는 중](images/manual/m07-command.png)

공장 Linux PC 의 터미널에 붙여 넣습니다. 관리자 비밀번호를 한 번 묻습니다.

```bash
curl -fsSL https://github.com/waceinc/vexplor-edge/releases/latest/download/get.sh | sudo sh -s -- --server https://aas.factory-cloud.example --code TS8M-66F9-KXJ6
```

이 한 줄이 하는 일은 다섯 가지입니다.

1. 그 PC 의 CPU(x64 · arm64)에 맞는 꾸러미를 최신 릴리스에서 내려받습니다
2. 같은 릴리스의 `SHA256SUMS` 와 대조합니다 — 다르면 설치하지 않고 멈춥니다
3. 프로그램을 `/opt/vexplor-edge` 에, 설정을 `/etc/vexplor-edge/edge.json` 에 둡니다
4. 이 PC 에서 서명 키를 만들고 코드로 서버에 등록합니다
5. systemd 서비스 `vexplor-edge` 를 켜고, 부팅할 때마다 자동으로 시작되게 합니다

실제 출력(깨끗한 Ubuntu, arm64):

```text
VEXPLOR Edge 1.0.0 (linux-arm64) — downloading
checked against SHA256SUMS
{"time":"2026-10-18T05:18:06.922Z","level":"info","message":"registered as dev_8760c38b60d8a808 — its read list is already approved; it reads as soon as the service starts"}
installed and started: systemctl status vexplor-edge · journalctl -u vexplor-edge
Done. Open the server's 「원격 수집기 (Remote collectors)」 screen: this PC shows as Receiving once values arrive.
If the list was not approved with the command, approve it there — it reads nothing before that.
```

명령 뒤에 붙일 수 있는 선택:

| 선택 | 뜻 |
|---|---|
| `--proxy http://host:port` | 현장 프록시(5-3절) |
| `--ca-file corp-ca.pem` | 서버 인증서를 사설 인증 기관이 발급했을 때 그 인증서(12-2절) |
| `--credentials-file credentials.json` | PLC 사용자 이름 · 비밀번호 파일(12-3절) |
| `--name "1라인"` | 서버 목록에 보일 이름. 기본은 PC 이름(hostname) |
| `--no-service` | 서비스를 등록하지 않음(시험용 · 컨테이너) |

### 5-5. 연결 확인

명령을 붙여 넣은 PC 가 서버에 등록되는 순간 화면이 저절로 바뀝니다. 기다리는 동안 화면은 3초마다 목록을 다시 불러옵니다.

![「연결되었습니다 — press-line-1」 받는 중](images/manual/m08-arrived.png)

**「완료」** 를 누르면 목록만 남습니다. 녹색 **「받는 중」** 이 보이면 연결이 끝난 것입니다.

![연결된 수집기 목록](images/manual/m09-list.png)

## 6. 승인 — 수집기가 무엇을 읽을지 정하기

수집기는 **사람이 승인한 목록만** 읽습니다. 승인하는 방법은 두 가지입니다.

| 방법 | 언제 |
|---|---|
| 명령을 만들 때 함께 승인(「이 목록을 바로 읽게 승인」 켬) | 보통의 경우. 붙여 넣으면 바로 읽습니다 |
| 연결된 뒤 따로 승인(끔) | 공장 PC 를 먼저 연결해 두고, 읽을 목록은 현장 확인 뒤 정할 때 |

### 6-1. 따로 승인하기

「이 목록을 바로 읽게 승인」을 끄고 명령을 만들면 안내가 「연결된 뒤 이 화면에서 읽을 목록을 승인해야 값이 들어옵니다」로
바뀝니다.

![바로 승인을 끈 명령](images/manual/m10-noapprove-command.png)

공장 PC 가 연결되면 **「승인 대기」** 로 나옵니다. 이때 수집기는 아무것도 읽지 않고, 10초마다 서버에 승인 여부를 묻습니다.

![연결되었지만 승인 대기](images/manual/m11-pending-arrived.png)

**「목록 보고 승인」** 을 누르면 이 수집기가 읽게 될 설비 · 주소 · 태그 수가 나옵니다. 확인하고 **「이 목록으로 승인」** 을
누릅니다.

![승인 전 목록 미리 보기](images/manual/m12-preview.png)

10초 안에 수집기가 승인을 알아채고 읽기 시작합니다.

![승인 뒤 — 두 수집기 모두 받는 중](images/manual/m13-approved.png)

### 6-2. 설비 파일이 바뀌면 — 「다시 승인」

승인한 뒤 설비 파일의 수집 연결이 바뀌어도(태그 추가 · 주소 변경 · 파일 추가) 수집기는 **승인한 그때의 목록을 계속
읽습니다.** 목록이 모르는 사이에 늘어나지 않게 하려는 것입니다. 수집기 줄에 「승인한 뒤 파일이 바뀌었습니다」가 나오고
**「다시 승인」** 단추가 생깁니다. 눌러서 새 목록을 확인하고 승인하면 그때부터 새 목록을 읽습니다.

명령을 만드는 동안 다른 사람이 파일을 바꿨다면 서버는 그 명령을 거절하고(목록이 바뀜) 카드가 새 목록을 다시
보여 줍니다. 본 것과 다른 목록을 승인하는 일은 없습니다.

## 7. 받은 값 보기

값은 원격 수집기 창이 아니라 **그 설비 파일** 에서 봅니다. 파일을 열면 오른쪽 「수집」 칸에 값이 10초마다 들어오고,
원격 수집기가 보내는 동안 「받는 중」이 붙습니다.

![설비 파일의 「수집」 칸 — 원격 수집기가 보낸 값](images/manual/m16-collect.png)

| 표시 | 뜻 |
|---|---|
| 최근 값 · 시각 | 수집기가 PLC 에서 읽은 마지막 값과 그 시각 |
| (빈 값) + 품질 코드 | PLC 가 값을 주지 못한 태그(예: `BadDeviceFailure`). 수집기는 가짜 값을 만들지 않고 빈 값과 이유를 그대로 보냅니다. Modbus TCP · MQTT 는 품질 코드 없이 빈 값만 보입니다(3-9절) |
| 하루 상태 | 그날의 가동 · 정지 · 알람 띠 |

같은 값은 AAS Studio 의 REST API(`?live=true`)와 연동(MES · ERP · CMMS)으로도 나갑니다 — 서버 안 수집기로 받은 값과
똑같이 다룹니다.

## 8. 수집기 상태 읽기

원격 수집기 창은 10초마다 목록을 다시 불러옵니다. 각 줄의 표시는 다음과 같습니다.

| 배지 | 뜻 | 할 일 |
|---|---|---|
| **받는 중** | 최근 3분 안에 묶음이 왔습니다 | 없음 |
| **첫 값 기다리는 중** | 승인했지만 아직 묶음이 오지 않았습니다 | 1~2분 기다립니다 |
| **승인 대기** | 연결됐지만 읽을 목록을 승인하지 않았습니다 | 「목록 보고 승인」(6-1절) |
| **일시 정지 중** | 사람이 멈췄습니다 | 「다시 시작」 |
| **끊김** | 3분 넘게 소식이 없습니다 | 아래 끊김 참고 |
| **해지됨** | 해지했습니다. 되돌릴 수 없습니다 | 다시 쓰려면 새 명령으로 연결 |

줄 아래 숫자:

| 표시 | 뜻 |
|---|---|
| 마지막 수신 | 서버가 마지막으로 묶음을 받은 시각 |
| 받은 값 | 이 수집기에서 받아 저장한 값의 누적 수 |
| 읽는 태그 | 승인한 목록의 태그 수 |
| 설비 연결 n/m | 수집기가 붙어 있는 설비 수 / 승인한 설비 수. 모자라면 「설비 연결 오류: …」에 이유가 나옵니다 |
| 보내지 못하고 쌓인 묶음 | 통신이 끊긴 동안 공장 PC 에 쌓였다가 지금 보내고 있는 묶음(14절) |
| 판 | 수집기가 마지막 묶음에 적어 보낸 지금 판(등록할 때의 판이 아닙니다) |

**끊김.** 수집기는 값이 없어도 1분에 한 번은 묶음을 보냅니다. 3분 넘게 아무것도 오지 않으면 「끊김」으로 바뀌고 확인할 곳을
알려 줍니다.

![3분 넘게 소식이 없는 수집기 — 끊김](images/manual/m15-silent.png)

확인 순서: ① 공장 PC 가 켜져 있는지 ② `systemctl status vexplor-edge`(10절) ③ 서버로 나가는 443 · 프록시가 열려 있는지
④ `journalctl -u vexplor-edge` 의 `read list not reachable` · `sending paused` 기록(18절). 통신이 복구되면 쌓인 묶음이
순서대로 들어오고 「받는 중」으로 돌아옵니다 — 끊긴 동안의 값도 잃지 않습니다.

## 10. 공장 PC 에서 보기 — 서비스 · 기록 · 파일

| 하려는 것 | 명령 |
|---|---|
| 실행 중인지 | `systemctl status vexplor-edge` |
| 기록 보기(실시간) | `journalctl -u vexplor-edge -f` |
| 오늘 기록 | `journalctl -u vexplor-edge --since today` |
| 다시 시작(설정을 바꾼 뒤) | `sudo systemctl restart vexplor-edge` |
| 멈추기 | `sudo systemctl stop vexplor-edge` |
| 판 확인 | `/opt/vexplor-edge/vexplor-edge --version` |

기록은 한 줄에 JSON 하나입니다(시각 · 수준 · 메시지). 정상일 때의 예:

```text
{"time":"…","level":"info","message":"read list ca22b55e3fe65985 (approved): 1 interface(s)"}
{"time":"…","level":"info","message":"running as dev_8760c38b60d8a808, boot 4be5b497-…"}
```

| 위치 | 내용 | 권한 |
|---|---|---|
| `/opt/vexplor-edge/vexplor-edge` | 프로그램(실행 파일 하나) | root |
| `/etc/vexplor-edge/edge.json` | 설정(11절) | root 쓰기, 서비스 계정 읽기 |
| `/etc/vexplor-edge/ca.pem` · `credentials.json` | 설치 때 넘긴 사설 인증서 · PLC 비밀번호(있을 때만) | root 쓰기, 서비스 계정 읽기 |
| `/var/lib/vexplor-edge/identity.json` | 장치 번호와 이 PC 의 서명 키. **밖으로 나가지 않습니다** | 서비스 계정만 |
| `/var/lib/vexplor-edge/queue` | 보내기를 기다리는 묶음 | 서비스 계정만 |
| `/var/lib/vexplor-edge/refused` | 서버가 형식 오류로 거절한 묶음(사람이 보도록 남김) | 서비스 계정만 |
| `/var/lib/vexplor-edge/opcua-pki` | OPC UA 인증서(12-4절) | 서비스 계정만 |
| `/etc/systemd/system/vexplor-edge.service` | 서비스 정의 | root |

서비스는 전용 계정 `vexplor-edge` 로, 권한을 줄인 상태로 동작합니다 — 새 권한을 얻지 못하고, 시스템은 읽기 전용이며,
쓸 수 있는 곳은 `/var/lib/vexplor-edge` 하나입니다.

## 11. 설정 파일 `edge.json`

설치기가 만든 `/etc/vexplor-edge/edge.json` 에는 보통 항목 세 개가 들어 있습니다.

```json
{ "server": "https://aas.factory-cloud.example", "stateDir": "/var/lib/vexplor-edge", "name": "press-line-1" }
```

전체 항목(바꾼 뒤 `sudo systemctl restart vexplor-edge`):

| 항목 | 기본 | 뜻 |
|---|---|---|
| `server` | (필수) | 서버 주소. **https** 만 받습니다(같은 PC 안 `http://localhost` 만 예외). 주소가 틀리면 시작하지 않습니다 |
| `stateDir` | (필수) | 키 · 대기열 · 인증서를 두는 폴더 |
| `name` | `VEXPLOR Edge` | 서버에 보일 이름(목록에는 PC 이름이 함께 나옵니다) |
| `proxy` | 없음 | `http://host:port` 형식의 HTTP CONNECT 프록시 |
| `caFile` | 없음 | 서버 인증서를 발급한 사설 인증 기관의 PEM |
| `credentialsFile` | 없음 | PLC 사용자 이름 · 비밀번호(12-3절) |
| `opcua.pkiDir` | `<stateDir>/opcua-pki` | OPC UA 인증서 폴더 |
| `opcua.trustFirstUse` | `false` | 처음 보는 OPC UA 서버 인증서를 신뢰할지(12-4절) |
| `opcua.mode` | `"poll"` | `"poll"`(주기마다 읽기) 또는 `"subscribe"`(바뀐 값만, 13절) |
| `opcua.deadband` | `0` | 구독 때 아날로그 태그의 불감대(절댓값) |
| `opcua.resendMs` | `300000` | 구독 때 값이 그대로여도 다시 보내는 간격(5분) |
| `flushIntervalMs` | `5000` | 모은 값을 묶음으로 만드는 간격(5초 — 1분에 12번) |
| `maxQueuedBatches` | `100000` | 디스크에 쌓아 둘 묶음 상한 |
| `maxQueueDays` | `30` | 보내지 못한 묶음을 보관하는 날 수 |
| `update.manifestUrl` · `update.publicKey` | 없음 | 새 판 알림(15절). 둘 다 있어야 켜집니다 |

상대 경로는 설정 파일이 있는 폴더 기준입니다. 읽는 주기는 설정 파일이 아니라 서버가 읽을 목록에 담아 보냅니다 —
기본 5초이고, 승인할 때 설비 · 태그마다 다르게 정할 수도 있습니다(3-1절).

## 12. 프록시 · 사설 인증서 · PLC 비밀번호 · OPC UA 인증서

### 12-1. 프록시

설치할 때 `--proxy http://proxy.plant.local:3128` 을 붙입니다(또는 화면의 프록시 칸에 넣습니다). 나중에 바꾸려면 `edge.json` 의 `proxy` 를
고치고 다시 시작합니다. 프록시는 서버 주소의 443 으로 CONNECT 를 허용해야 합니다. 프록시가 거절하면 기록에
`proxy refused CONNECT …: 403` 이 남습니다.

### 12-2. 사설 인증 기관

서버 인증서를 회사 인증 기관이 발급했으면 그 기관 인증서(PEM)를 `--ca-file corp-ca.pem` 으로 넘깁니다.
`/etc/vexplor-edge/ca.pem` 으로 복사되고 `caFile` 이 설정됩니다.

### 12-3. PLC 비밀번호

PLC 사용자 이름 · 비밀번호는 서버에도 설비 파일에도 넣지 않습니다. 설비 파일의 수집 연결에는 이름표(`credentialRef`)만
두고, 실제 값은 공장 PC 의 파일에 둡니다.

```json
{ "opc.tcp://10.0.0.5:4840": { "userName": "reader", "password": "…" } }
```

설치 때 `--credentials-file credentials.json` 으로 넘기면 `/etc/vexplor-edge/credentials.json`(root · 서비스 계정만 읽기)으로
복사됩니다. 이름표에 맞는 항목이 없으면 그 설비는 연결되지 않고 「설비 연결 오류: no credential named … in the
credentials file」이 화면에 나옵니다.

### 12-4. OPC UA 인증서

수집기는 처음 시작할 때 `opcua-pki` 에 자기 인증서를 만듭니다. 보안 모드가 `Sign` · `SignAndEncrypt` 인 OPC UA 서버는
양쪽이 서로의 인증서를 신뢰해야 연결됩니다.

1. 처음 보는 PLC 인증서는 거절되어 `/var/lib/vexplor-edge/opcua-pki/rejected` 에 놓입니다
2. 확인한 뒤 그 파일을 `opcua-pki/trusted/certs` 로 옮기고 다시 시작합니다
3. PLC(OPC UA 서버) 쪽에서도 수집기 인증서(`opcua-pki/own/certs`)를 신뢰 목록에 넣습니다

설치 시험처럼 확인 절차를 건너뛰어도 되는 곳에서는 `"opcua": { "trustFirstUse": true }` 로 처음 본 인증서를 신뢰하게
할 수 있습니다. 운영에서는 권하지 않습니다.

## 13. 바뀐 값만 보내기 (OPC UA 구독 · 불감대)

기본(`"poll"`)은 정한 주기마다 모든 태그를 읽어 보냅니다. 회선이 좁거나 태그가 많으면 OPC UA 구독으로 바꿉니다.

```json
{ "server": "…", "stateDir": "/var/lib/vexplor-edge",
  "opcua": { "mode": "subscribe", "deadband": 1.0, "resendMs": 300000 } }
```

- `subscribe` — PLC 가 태그마다 정한 주기로 값을 살피고 **바뀌었을 때만** 보냅니다
- `deadband` — 아날로그(실수) 태그에서 이보다 작은 변화는 보내지 않습니다. **카운터 · 상태 · 글자 태그에는 적용하지
  않습니다**(생산 수량이 1씩 오를 때 불감대 1을 주면 절반이 사라지기 때문입니다)
- `resendMs` — 값이 그대로여도 이 간격마다 다시 보냅니다. 그래야 서버가 「안 바뀜」과 「못 읽음」을 구분할 수 있습니다

실측(PLC 모의기, 태그 6개 · 1초 · 5분):

| 방식 | 보낸 값 | 크기 |
|---|---|---|
| 매번 읽기(`poll`) | 1 794개 | 283 KB |
| 구독(`subscribe`) | 729개 | 130 KB(−54%) |
| 구독 + 불감대 1.0 | 436개 | 88 KB(−69%) |

PLC 가 구독을 거절하면 수집기는 기록에 `subscription refused, reading every … ms instead` 를 남기고 주기 읽기로 바꿔
계속 읽습니다.

## 14. 통신이 끊겼을 때 — 대기열

- 읽은 값은 먼저 공장 PC 디스크(`queue`)에 묶음으로 쌓이고, 서버가 받았다고 답한 묶음만 지웁니다
- 서버가 답하지 않으면(통신 끊김 · 서버 재시작 · 429 · 5xx) 간격을 늘려 가며(최대 5분) 같은 묶음을 다시 보냅니다
- 통신이 복구되면 쌓인 묶음을 **오래된 것부터 순서대로** 보냅니다. 화면에 「보내지 못하고 쌓인 묶음 n개」가 보이다가 0이
  됩니다
- 서버는 같은 묶음을 두 번 받아도 한 번만 저장합니다(장치 · 부팅 · 순번으로 구분)
- `maxQueuedBatches`(10만)를 넘거나 `maxQueueDays`(30일)보다 오래되면 가장 오래된 것부터 버리고, 버린 수를 다음 묶음의
  상태에 적어 보냅니다 — 알리지 않고 버리는 일은 없습니다
- 서버가 형식 오류로 거절한 묶음은 `refused` 폴더로 옮겨 사람이 볼 수 있게 둡니다

## 15. 판 올리기 · 새 판 알림

수집기는 스스로 내려받거나 설치하지 않습니다. 판 올리기는 사람이 합니다. 등록(키 · 장치 번호)은
`/var/lib/vexplor-edge` 에 있으므로 프로그램 파일만 바꾸면 됩니다 — 다시 등록하거나 다시 승인할 필요가 없습니다.

```bash
V=1.0.1    # 올릴 판
A=x64      # arm64 PC 는 arm64
curl -fsSLO https://github.com/waceinc/vexplor-edge/releases/download/v$V/vexplor-edge-$V-linux-$A.tar.gz
curl -fsSLO https://github.com/waceinc/vexplor-edge/releases/download/v$V/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
tar xzf vexplor-edge-$V-linux-$A.tar.gz
sudo install -m 0755 vexplor-edge-$V/vexplor-edge /opt/vexplor-edge/vexplor-edge
sudo systemctl restart vexplor-edge
/opt/vexplor-edge/vexplor-edge --version
```

서버 화면의 판 표기는 다음 묶음부터 새 판으로 바뀝니다. 판마다 바뀐 것은
[Releases](https://github.com/waceinc/vexplor-edge/releases)에 있습니다.

**새 판 알림(선택).** `edge.json` 에 `"update": { "manifestUrl": "https://…", "publicKey": "<릴리스 키>" }` 를 두면 하루에
한 번 릴리스 안내 파일을 읽고, 서명이 맞는 새 판이 있으면 기록(`update available: …`)과 다음 묶음의 상태로 알립니다.
서명이 맞지 않는 안내는 무시하고 기록만 남깁니다. 이 두 값이 없으면 업데이트를 묻는 요청 자체를 보내지 않습니다.

## 16. 인터넷이 막힌 PC 에 직접 설치

공장 PC 가 GitHub 에 닿지 못하면 다른 PC 에서 내려받아 옮깁니다.

1. [Releases](https://github.com/waceinc/vexplor-edge/releases)에서 `vexplor-edge-<판>-linux-x64.tar.gz`(또는 `linux-arm64`)와
   `SHA256SUMS` 를 받습니다
2. USB 등으로 공장 PC 에 옮긴 뒤:

```bash
sha256sum -c SHA256SUMS --ignore-missing
tar xzf vexplor-edge-<판>-linux-x64.tar.gz && cd vexplor-edge-<판>
sudo ./install.sh --server https://aas.factory-cloud.example --code TS8M-66F9-KXJ6
```

코드는 서버 화면이 만든 명령의 `--code` 값입니다. `install.sh` 는 `get.sh` 와 같은 선택(`--proxy` · `--ca-file` ·
`--credentials-file` · `--name` · `--no-service`)을 받습니다. 공장 PC 는 서버 443(또는 프록시)에는 닿아야 합니다.

## 17. 지우기

공장 PC 에서:

```bash
sudo systemctl disable --now vexplor-edge
sudo rm -r /opt/vexplor-edge /etc/vexplor-edge /etc/systemd/system/vexplor-edge.service
sudo systemctl daemon-reload
# 대기열과 키까지 지울 때만
sudo rm -r /var/lib/vexplor-edge
sudo userdel vexplor-edge
```

서버에서는 그 수집기를 **해지** 합니다(9절). 해지하지 않고 PC 만 지우면 목록에 「끊김」으로 남습니다.

## 18. 문제가 생기면

**설치할 때(`get.sh` · `install.sh`)**

| 나온 메시지 | 원인 | 할 일 |
|---|---|---|
| `this installer is for Linux (Windows is in preparation)` | Linux 가 아닌 PC | Linux PC 또는 Linux VM |
| `unsupported CPU: …` | x64 · arm64 가 아닌 CPU | 지원 CPU 의 PC |
| `run as root` | `sudo` 없이 실행 | 명령을 그대로(`| sudo sh …`) 붙여 넣기 |
| `download failed: …` | GitHub 에 닿지 않음 | 프록시 뒤라면 `https_proxy` 를 설정하고 `sudo -E sh` 로 실행(sudo 는 기본으로 환경 변수를 넘기지 않습니다), 아니면 16절 직접 설치 |
| `… does not match SHA256SUMS — not installed` | 내려받은 파일이 릴리스와 다름(중간 변조 · 손상) | 설치하지 않은 상태입니다. 다시 받고, 반복되면 네트워크 장비 확인 |
| `quotes and backslashes are not allowed` | 주소 · 이름에 따옴표 · 역슬래시 | 따옴표 없이 입력 |
| `registration refused: 401 RegistrationCodeInvalid` | 코드가 틀렸거나, 이미 쓰였거나, 24시간이 지남 | 화면에서 명령을 새로 만들기 |
| `registration refused: 429 RateLimited` | 짧은 시간에 등록을 여러 번 시도 | 잠시 뒤 다시 |
| `server must be https:// (plain http only on this machine)` | 서버 주소가 http | https 주소로(서버 앞에 HTTPS) |

**실행 중일 때(`journalctl -u vexplor-edge`)**

| 기록 · 화면 | 원인 | 할 일 |
|---|---|---|
| 화면 「끊김」, 기록 `read list not reachable: …` | 서버로 나가는 길이 막힘 | 443 · 프록시 · DNS 확인. 값은 대기열에 쌓이고 있습니다 |
| `sending paused … ms: no answer: …` | 서버가 답하지 않음 | 서버 상태 확인. 같은 묶음을 다시 보냅니다 |
| `sending paused … ms: 401 ClockSkew` | 공장 PC 시계가 서버와 5분 넘게 다름 | PC 시간 동기화(NTP) 켜기 |
| `proxy refused CONNECT …` | 프록시가 서버 443 을 막음 | 프록시에 서버 주소 허용 |
| `ALARM: read list refused: 403 DeviceRevoked — sending stopped, the queue is kept` | 서버에서 해지됨 | 의도한 것이면 17절로 지우기. 아니면 새 명령으로 다시 연결 |
| `ALARM: … 401 UnknownDevice …` | 서버에 이 장치 기록이 없음(서버 데이터를 새로 만듦) | 새 명령으로 다시 연결(17절로 지운 뒤 설치) |
| `not registered — run register with a code first` | 등록 없이 서비스가 시작됨 | 화면에서 명령을 만들어 다시 설치 |
| 화면 「설비 연결 0/1」 · 「설비 연결 오류: …」 | PLC 에 닿지 않거나 거절 | PLC 주소 · 포트 방화벽 · OPC UA 인증서(12-4절) · 비밀번호(12-3절). 1.0.1 부터는 수집기가 최대 60초 간격으로 다시 붙어 보므로, PLC 를 고치면 저절로 읽습니다(3-9절) |
| 기록 `… reconnecting in … s` · `reconnect attempt N failed` | PLC · 브로커가 꺼졌거나 다시 시작됨(1.0.1 부터) | PLC · 브로커를 켜면 `connected again` 이 남고 다시 읽습니다. 계속 실패하면 위 행 확인 |
| PLC · 브로커를 다시 켠 뒤 「받는 중」인데 빈 값만(1.0.0) | 1.0.0 은 끊긴 설비 연결을 다시 붙이지 않음 | `sudo systemctl restart vexplor-edge`, 또는 1.0.1 이상으로 판 올리기(15절) |
| 화면 「승인 대기」가 그대로 | 승인하지 않음 | 「목록 보고 승인」(6-1절) |
| 화면 「승인한 뒤 파일이 바뀌었습니다」 | 설비 파일의 수집 연결이 바뀜 | 「다시 승인」(6-2절) |
| 값 칸에 (빈 값) + `Bad…` | PLC 가 그 태그 값을 주지 못함 | PLC 쪽 태그 상태 확인. 수집기 문제가 아닙니다 |

## 19. 보안 — 하는 일과 하지 않는 일

| | |
|---|---|
| **읽기만** | PLC · 제어기에 쓰는 코드가 없습니다. 읽는 코드는 AAS Studio 서버 안 수집기와 같은 라이브러리입니다 |
| **밖으로만** | 서버 주소 443(또는 프록시)으로만 나갑니다. 포트를 열지 않고, 서버가 공장 안으로 들어오는 길이 없습니다 |
| **승인한 목록만** | 사람이 서버에서 승인한 목록만 읽습니다. 목록이 바뀌어도 다시 승인할 때까지 옛 목록만 읽습니다 |
| **요청마다 서명** | 등록할 때 공장 PC 에서 Ed25519 키를 만들고 모든 요청에 서명합니다. 개인 키는 PC 를 떠나지 않습니다 |
| **비밀번호는 PC 에만** | PLC 비밀번호는 공장 PC 파일에만 있고, 서버 · 설비 파일 · 읽을 목록에는 이름표만 있습니다 |
| **원격 정지 없음** | 서버가 수집기에 내리는 명령이 없습니다. 해지는 서버가 요청을 거절하는 것이고, 수집기는 스스로 보내기를 멈춥니다 |
| **자동 설치 없음** | 새 판은 알림만 받을 수 있고, 설치는 사람이 합니다 |

수집기가 연결하는 곳은 아래가 전부입니다.

| 목적지 | 이유 | 언제 |
|---|---|---|
| 설정의 서버 주소 443(또는 `proxy`) | 등록 · 읽을 목록 · 묶음 | 늘 |
| 승인한 목록의 PLC 주소(OPC UA · Modbus TCP · MQTT) | 값 읽기 | 승인 뒤 |
| `update.manifestUrl` | 새 판 알림(하루 한 번) | 설정했을 때만 |
| GitHub 릴리스 | 설치 때 꾸러미 내려받기(`get.sh`) | 설치할 때만 |

보안 문제를 찾으면 [SECURITY.ko.md](../SECURITY.ko.md)의 방법으로 알려 주십시오.
